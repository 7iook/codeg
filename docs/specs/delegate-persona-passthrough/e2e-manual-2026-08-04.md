### 用例 #7 · 并发人格隔离(真进程)

**目标**:同时发两条 Kiro delegation `subagent_type: codeg-e2e-probe-a` / `codeg-e2e-probe-b`,两子进程 argv 各自的 `--agent`,首轮 prompt marker 互不污染。

**执行**:**unverified — 同 #2 原因 + 并发需 UI 里同时触发**。

**若要真跑**(交给用户):

```powershell
# 1. 落两份 fixture
foreach ($tag in 'a','b') {
  @{
    subagent_name = "codeg-e2e-probe-$tag"
    description   = "Stage 8 并发隔离探针 $tag"
    tools         = @()
  } | ConvertTo-Json | Out-File "$env:USERPROFILE\.kiro\agents\codeg-e2e-probe-$tag.json" -Encoding UTF8
  "SPEC_MARKER_PROBE_$($tag.ToUpper())" | Out-File "$env:USERPROFILE\.kiro\agents\codeg-e2e-probe-$tag.md" -Encoding UTF8
}

# 2. 在 codeg 里并发 delegate 两条 kiro + 不同 subagent_type · 快速切两卡片
# 3. 观察 kiro-cli 进程列表 argv 各自的 --agent 值(应互不混淆):
Get-CimInstance Win32_Process -Filter "Name='kiro-cli.exe' OR Name='node.exe'" |
    Where-Object { $_.CommandLine -match 'codeg-e2e-probe' } |
    Select ProcessId, CommandLine
# 4. 子会话首轮 marker 互不污染
# 5. 清理: rm ~/.kiro/agents/codeg-e2e-probe-a.{json,md}, codeg-e2e-probe-b.{json,md}
```

**A 部分相关证据**:`broker_persona.rs::concurrent_same_agent_distinct_personas_do_not_cross`(P5)已在 spawn_args 层锁死「两条 KiroPersona 并发的 launch_option 不串扰」· `persona_merge_order::merged_launch_option_translates_to_agent_argv_end_to_end` 已锁「merge → argv」翻译不变式;两条合起来意味 argv 一定分家。**真进程观察等于把这条链再多一步验证到 OS 层。**

### 用例 R7.1 · Kiro 子进程死亡后恢复(观察记录型)

**目标**:起 Kiro + `subagent_type: codeg-e2e-probe`,完成首轮后 `taskkill /PID <kiro-cli pid> /F`;`continue_with_session` 触发 `spawn_for_resume`;观察:(a) kiro-cli 是否 reload `codeg-e2e-probe.json`?(b) 二轮响应是否反映人格行为?(c) codeg `applied_persona` 首次值在恢复后 UI 是否仍显示?

**执行**:**unverified — SUB 环境不能起 host + kill 真进程**。**这是「观察记录」型任务而非「必须通过」型**(dispatch 明确 · design.md `## Known Limitations` 段说 codeg 不承诺 kiro-cli 内部行为)。

**若要真跑**:

```powershell
# 前置:落 codeg-e2e-probe.json 到 ~/.kiro/agents/
# 步骤:
# 1. codeg host 里 kiro + subagent_type=codeg-e2e-probe,发 "第一条消息"
# 2. 等待首轮 completed,记录 UI 卡片显示的 applied_persona 首次值(应为 native/@codeg-e2e-probe)
# 3. 找到 kiro-cli 子进程 PID:
Get-CimInstance Win32_Process -Filter "Name='kiro-cli.exe' OR Name='node.exe'" |
    Where-Object { $_.CommandLine -match 'codeg-e2e-probe' } | Select ProcessId, CommandLine
# 4. taskkill /PID <上一步的 pid> /F
# 5. codeg host 里 continue_with_session 发 "第二条消息"
# 6. 观察记录三点:
#    (a) kiro-cli 是否重启? 新进程 argv 是否含 --agent codeg-e2e-probe?
#        (spawn_for_resume 在 stage 5 明确不带 launch_option = 只带 --session,不重传 --agent)
#    (b) 二轮响应是否仍表现人格(取决于 kiro-cli 内部是否 reload 人格 —— 是 kiro-cli 侧行为,codeg 不控制)
#    (c) UI 卡片的 applied_persona 首次值是否仍显示?(应该保留首次值,不因恢复而清空 —— stage 7 前端 model 层保证)
```

**预期观察**(基于代码分析,未实测):
- (a) 大概率 **no**:`ConnectionSpawner::spawn_for_resume` 签名不接 `LaunchOption`(R7.4 · 保护 kiro-cli 不重复提名人格 · spawner.rs 明写)· 新进程 argv 只带 `--session <id>`,无 `--agent`
- (b) 取决于 kiro-cli 是否把 `--agent` 状态写进 session state · 如否,resume 后回退默认人格 · **这是 kiro-cli 内部行为,codeg 不控制,不承诺**
- (c) codeg 前端 `applied_persona` 是 spawn-Ok 时定并存进 running_task,不会因 resume 而清空 · UI 应显示首次值
